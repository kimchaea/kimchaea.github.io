좋은 숫자보다 먼저 평가 방법을 검증했습니다.

동일한 고장 사례의 유사 시계열이 학습과 시험에 함께 들어가면 성능이 과대평가될 수 있습니다. 이를 피하기 위해 고장 사례 전체를 시간순으로 분리하고, Train–Test 간 고장 및 원본 데이터 중복이 0인지 확인했습니다.

01 · PROBLEM

설비가 고장 나기 전에,
얼마나 시간이 남았는지 알 수 있을까?

반도체 제조 설비의 예기치 않은 고장은 생산 중단과 품질 저하로 이어질 수 있습니다. 이 프로젝트에서는 냉각 계통 압력이 과도하게 높아지는 Flowcool Pressure Too High 고장을 대상으로, 센서 변화만으로 고장까지 남은 시간을 예측할 수 있는지 확인했습니다.

데이터

PHM Society 2018 Data Challenge의 Ion Mill Etch 반도체 제조 설비 데이터

입력

압력, 전압, 전류, 가스, 회전, 사용량 등 16개 설비 상태 변수의 시계열

예측 목표

고장 약 33분 전 이내 구간에서 현재 시점부터 실제 고장까지 남은 시간

02 · METHOD

같은 고장을 외운 모델이 아니라,
미래 고장을 처음 보는 모델로 평가

초기 분석에서는 무작위로 겹치는 시계열 창을 나누면 같은 고장의 매우 유사한 데이터가 학습과 시험에 함께 포함될 수 있음을 확인했습니다. 최종 평가는 고장 사례 자체를 분리하는 방식으로 다시 설계했습니다.

STEP 01원본 4초 간격 센서 데이터
STEP 02실제 설비 가동 상태만 선별
STEP 03고장 전 2,000초 구간 고정
STEP 04최근 60개 측정값 ≈ 약 4분
STEP 052-layer GRU로 시간 패턴 학습
STEP 06완전히 이후의 고장 사례로 시험
Strict evaluation design과거 고장 7건은 학습, 이후 고장 1건은 검증, 더 이후 고장 3건은 시험으로 고정했습니다. Train–Validation–Test 사이의 고장 사례와 원본 센서 row가 서로 겹치지 않음을 코드로 확인했습니다.

04 · SENSOR ANALYSIS

고장 전에 크게 변하는 센서와
AI가 실제로 활용한 센서는 같지 않았다

최종 모델을 다시 학습하지 않은 채, 입력 센서를 하나씩 학습 데이터의 평균 상태로 가린 뒤 예측오차 변화를 확인했습니다. 센서를 가렸을 때 오차가 증가할수록, 고정된 GRU가 그 입력 정보에 더 의존했다고 해석했습니다.

상태 변수입력을 가렸을 때 Macro RMSE 변화두 미래 고장에서 RMSE 악화해석
ETCHSUPPRESSORCURRENT+476.85 s2 / 2가장 높은 모델 의존도
ETCHSOURCEUSAGE+183.02 s2 / 2설비 사용상태 정보와 연관 가능
IONGAUGEPRESSURE+142.90 s2 / 2압력 상태 정보와 연관
FLOWCOOLFLOWRATE+25.46 s2 / 2다변량 예측에서 보조 정보로 활용
FLOWCOOLPRESSURE-10.86 s0 / 2고장 전 증가 경향은 있었지만 독립 예측기여는 제한적
“고장 전에 값이 변한다”는 것과 “AI 예측에 꼭 필요한 정보다”는 것은 다른 질문이다.

예를 들어 FLOWCOOLPRESSURE는 학습에 사용한 7개 고장 사례 모두에서 고장 접근 시 증가 방향을 보였지만, 이를 가렸을 때 GRU의 RMSE는 증가하지 않았습니다. 따라서 단변량 변화만으로 핵심 예측변수라고 단정하지 않았습니다.

05 · VALIDATION & LIMITATIONS

결과의 범위를 함께 명시했습니다.

이 결과는 실제 생산라인 전체 성능을 입증한 것이 아니라, 소수의 완전히 분리된 미래 고장 사례를 대상으로 한 엄격한 일반화 스트레스 테스트입니다.

01시험 대상으로 계획한 미래 고장 3건 중 2건만 평가 가능했습니다. 1건은 60개 연속 측정값을 확보할 수 없어 모델 입력 자체를 만들 수 없었습니다.
02따라서 Test event coverage는 66.7%이며, 결과를 다수 설비·대규모 생산 환경 전체로 확대해석하지 않았습니다.
03모델의 예측 범위는 전체 설비 수명이 아니라 고장 2,000초(약 33분) 전 이내로 제한됩니다.
04센서 occlusion 결과는 모델이 활용한 정보의 정도를 보여줄 뿐, 해당 센서가 고장의 물리적 원인이라는 인과관계를 증명하지 않습니다.
05Sliding window는 같은 고장 내부에서 서로 겹치므로 window 개수보다 고장 event 단위 결과와 macro 지표를 우선 해석했습니다.
Project takeaway모델 성능을 높이는 것만큼, 학습과 시험 데이터가 실제 미래 상황을 제대로 모사하는지 확인하는 것이 중요했습니다. 평가 데이터의 중복 가능성을 확인한 뒤 고장 event 단위 시간순 분리로 재설계했고, 그 엄격한 조건에서도 평가 가능한 두 미래 고장 사례 모두에서 단순 기준모델 대비 오차 감소를 확인했습니다.
