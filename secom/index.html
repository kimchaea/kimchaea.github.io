정상 데이터가 압도적으로 많은 제조 데이터에서 불량을 얼마나 찾아낼 수 있을까?

결측률이 절반을 넘는 변수는 실제 관측값보다 대체값의 영향이 커질 수 있다고 판단해 제거했다. 남은 결측치는 극단값의 영향을 상대적으로 덜 받는 중앙값으로 대체했다. 불균형 처리는 우선 class_weight="balanced" 또는 동등한 sample weight를 사용하고, 인위적 샘플 생성 방식인 SMOTE는 초기 비교에서 제외했다.

교차검증에서도 전처리를 fold 안에 넣은 이유
각 fold의 Validation 정보를 이용해 결측률이나 상수 여부를 정하면 Validation 특성이 입력 변수 구성에 반영된다. 이를 막기 위해 FeatureFilter를 Pipeline 내부에 두고 각 training fold에서만 제거 변수를 학습했다. 실제 fold별 최종 변수 수는 444~450개로 달라졌다.

04 · OPERATING SCENARIOS

하나의 threshold 대신 비용·품질 목표·검사 자원으로 나눠 판단

05 · FALSE NEGATIVE ANALYSIS

20% 추가 검사 가정에서 놓친 불량은 왜 놓쳤을까?
